> **온라인 배포 완료** — 아래 기존 안내는 로컬 개발 버전 기록입니다.

- 유아 공통 링크: https://edupoplab.github.io/music-library/
- 교사 로그인: https://edupoplab.github.io/music-library/?page=teacher
- 관리자: https://edupoplab.github.io/music-library/?page=admin

온라인 버전은 GitHub Pages의 docs 폴더와 Supabase의 music-api 서버를 연결합니다. 최초 관리자는 소유자에게 전달한 하루 유효 일회용 링크로 설정합니다. 계정·반·곡 정보는 비공개 music 스키마, MP3와 썸네일은 비공개 music-media 버킷에 보관합니다. 교사 계정은 앱 자체 계정이며 Supabase Authentication 목록과 별개입니다.

초대 링크는 직접 전달하며 자동 이메일 발송은 아직 없습니다. 반별 연령 필드도 아직 구현되지 않았습니다. 실제 관리자 설정 후 MP3 업로드·재생 테스트를 이어서 진행합니다.

화면 수정 후 `node cloud/build-pages.mjs`로 docs를 다시 생성합니다. 서버 수정은 GitHub 반영 후 Supabase 함수의 고정 커밋 주소를 변경해 재배포해야 합니다. `cloud` 폴더에서 테스트 의존성을 설치하고 `node qa.mjs`를 실행하면 PostgreSQL 호환 환경에서 권한과 저장 흐름을 검증합니다.

# 새싹나라 우리 반 음악 도서관 v0.3

## 열어 보기
- 디자인 체험: http://127.0.0.1:4317/demo
- 태블릿 설정 체험: http://127.0.0.1:4317/demo/tablet
- 유아용 공통 링크: http://127.0.0.1:4317/listen
- 실제 교사 로그인 / 최초 관리자 설정: http://127.0.0.1:4317/teacher
- 실제 관리자 화면: http://127.0.0.1:4317/admin

디자인 체험은 예시 데이터입니다. 실제 자료와 분리되어 있고 새로고침하면 변경 사항이 사라집니다. 실제 로그인 화면에서 등록한 자료는 서버의 data 폴더에 저장됩니다. 실제 계정이나 비밀번호는 미리 만들어 두지 않았습니다.

## 구현한 흐름
1. 관리자 계정을 이 컴퓨터에서 처음 한 번 설정합니다. 비밀번호는 12자 이상입니다.
2. ‘교사·반 관리’에서 반 이름을 고치거나 반을 추가합니다.
3. 교사 이름·이메일·담당 반을 입력해 초대 링크를 만듭니다. 관리자가 해당 교사에게 직접 전달합니다. 이메일 자동 발송은 미연결 상태입니다.
4. 교사는 초대 링크에서 본인 비밀번호를 설정합니다. 초대는 7일 동안 한 번만 사용할 수 있습니다.
5. 전체 보관함에 MP3와 썸네일을 올리고 주제를 1~8개 붙입니다.
6. 담당 반에 곡을 담고 순서를 정합니다. ‘선택 저장’은 초안 저장이며 유아 화면에는 반영되지 않습니다.
7. ‘미리보기’ 후 ‘아이들에게 공개’를 누르면 반별 유아 화면이 갱신됩니다.
8. ‘유아용 공통 링크’에서 같은 주소를 한 번 복사해 놀이터에 등록합니다. 각 태블릿에서 교사가 인증하고 담당 반을 최초 한 번 지정합니다.

## 화면 구분
- 유아: 공개된 곡, 해당 곡에 붙은 주제만 표시합니다. 실제 유아 화면에는 관리 화면 버튼이나 다른 반 선택 목록이 없습니다. ‘반 설정’을 누르면 교사 재인증부터 진행합니다.
- 하트: 해당 기기의 듣고 싶은 목록입니다. 같은 태블릿에서는 하트가 공유됩니다. 기기와 반별로 저장됩니다.
- ‘내가 고른 노래’에서 아래 재생 버튼을 누르면 하트 목록이 시작됩니다. 각 곡을 선택한 횟수만큼 재생한 후 다음 곡으로 넘어갑니다. ‘계속 듣기’는 한 곡 무한 반복입니다.
- 교사: 전체 보관함 조회·곡 등록, 본인이 등록한 곡 정보 수정, 담당 반 목록 관리.
- 관리자: 모든 반 관리, 주제·교사 초대·담당 반 배정·계정 이용 중지·재설정 링크 발급.
- 노래 모음: 반별로 곡과 순서를 저장하고 다시 선택 목록으로 불러옵니다. 불러오기만으로 공개되지는 않습니다.

## 다시 실행
Node.js 24 이상에서 이 폴더를 열고 `node server.mjs`를 실행합니다. 외부 라이브러리 설치는 필요 없습니다.
현재 기본 주소는 127.0.0.1:4317이며 이 컴퓨터에서만 접속됩니다.

## 데이터
- data/library.sqlite: 계정, 반, 주제, 곡 정보, 선택·공개 목록, 초대 기록.
- data/media: MP3와 썸네일 원본.
- 비밀번호는 scrypt 해시, 세션·초대·재설정 토큰은 SHA-256 해시로 저장됩니다.
- MP3 25MB, PNG/JPG/WebP 썸네일 4MB 제한입니다.
- data 폴더를 웹 공개 폴더나 소스 저장소에 올리지 않습니다.
- 백업은 서버를 종료한 뒤 data 폴더 전체를 복사합니다. 온라인 서비스에는 별도의 자동 백업 운영이 필요합니다.

## 배포 전 남은 작업
이 버전은 로컬 개발·검증 버전입니다. 아직 온라인 배포나 실제 APK 설치 기기 검증을 마치지 않았습니다.
- 상시 실행 가능한 Node.js 24 서버와 영구 저장 디스크 준비.
- HTTPS 도메인과 역방향 프록시 연결. APP_ORIGIN을 실제 HTTPS 주소로 지정.
- 최초 관리자는 로컬에서 설정 후 안전한 경로로 데이터 이관. NODE_ENV=production 상태에서는 공개 최초 계정 생성을 금지합니다.
- HOST, PORT, DATA_DIR 환경변수 설정. production에서는 HTTPS 프록시 뒤에서 실행합니다.
- 초대 이메일 발송 서비스 연결(현재 관리자가 링크를 직접 전달).
- 관리자 본인의 비밀번호 분실 복구 절차, 자동 백업·모니터링 운영 마련.
- 운영 배포 시 /와 /demo의 디자인 체험 접근 정책 결정.
- 놀이터 등록과 APK 관련 작업은 사용자가 직접 진행합니다.
- 화면이 꺼지거나 다른 앱으로 이동한 뒤의 백그라운드 재생은 보장하지 않습니다.

현재 SQLite 서버는 단일 인스턴스 운영 구조입니다. 여러 서버를 동시에 운영하려면 공유 데이터베이스·음원 저장소로 전환해야 합니다. 정적 웹 호스팅만으로는 로그인·저장 API를 실행할 수 없습니다.

## v0.3 변경
공통 링크 `/listen`에서 최초 교사 인증 → 담당 반 선택 → 교사 로그인 종료 → 기기 반 유지 흐름을 사용합니다. 반 변경도 새 인증이 필요합니다. 실제 기기 권한은 서버의 devices 테이블과 HttpOnly 쿠키로 관리합니다. 설정 인증은 10분, 기기 쿠키는 최대 400일이며 방문 시 갱신됩니다. 데이터 삭제나 만료 시 재설정합니다. 자세한 내용은 integration/연결안내.md를 참고하세요.
